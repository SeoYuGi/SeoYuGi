# UNPREDICT (서유기) 기술 보고서

> 작성일 2026-09-06 · 대상 기간 2026-09-05 ~ 09-06 (집중 개발 스프린트)
> 스택: Unity 6 (URP) · Netcode for GameObjects · Unity Services Multiplayer (Relay/Session) · 순수 C# 전투 코어

3v3 실시간 그리드 전술 게임. 들개·길고양이 등 도시 동물 분대가 도시 관리 AI의 기계 복제군과
거점을 두고 싸운다. 이 문서는 최근 스프린트에서 구축·개선한 시스템을 계층별로 정리한 기술 기록이다.

---

## 1. 아키텍처 개요

```
[순수 C# 전투 코어]  CombatSystem / MoveSystem / RoundSystem / VisionSystem / GridModel
        │  (UnityEngine 비의존 — EditMode 테스트 가능, 결정론 판정)
[통합 계층]  BattleRunner (MonoBehaviour) — 시뮬 틱, 이벤트 구독, 연출 발주
        │
[표현 계층]  BattleHud(IMGUI 네온 킷) · GridView · UnitView · 절차 VFX(FxQuad/RingWave/War FX)
[네트워크]   NetBoot(퀵조인) · NetLobby(슬롯·시작) · NetSync(스냅샷 + 이벤트 릴레이)
```

- **호스트 권위 시뮬**: 전투 판정은 호스트에서만 진행. 클라이언트는 스냅샷 미러 + 이벤트 릴레이로 표현만 재구성한다.
- **텔레그래프 전투**: 즉발은 이동기뿐, 모든 타격·CC는 예고(TelegraphStrike) 후 판정. 판정 순서 = 설치 순서(결정론).
- **표 기반 밸런스**: 클래스·스킬 수치는 `ClassCatalog` 단일 표. UI 미리보기와 실제 판정이 같은 표를 참조해 어긋나지 않는다.

## 2. 네트워킹·동기화

### 2.1 퀵조인 매치메이킹
- `MatchmakeSessionAsync(QuickJoinOptions{Timeout 8s, CreateSession=true})` — 빈 세션에 합류하거나 방을 만든다.
- SDK가 NGO를 비동기로 띄우므로 **NGO 리스닝 대기 루프(10s)** 를 두고 `NetLobby.Begin()`을 호출 (CustomMessagingManager NRE 해소).
- 검색 중 **ESC 취소**: 잡힌 세션을 명시적으로 `LeaveAsync` — 유령 방에 다른 유저가 매칭되는 것을 방지.

### 2.2 스냅샷과 클라 시계
- 스냅샷 **12Hz → 20Hz** 상향 (유닛 스칼라 + 거점 게이지 + 시계).
- 클라는 시뮬을 돌리지 않아 `battle.time`이 스냅샷 사이에 얼어 있었다 →
  **프레임 로컬 외삽 + 스냅샷은 보정만**(전진은 즉시, 후퇴는 0.5s 이상일 때만) — 예고 카운트다운·펄스의 계단 현상 제거.
- 위치 적용은 `GridModel.ForceMove` 관용 동기 — 점유 맵이 어긋나 있어도 던지지 않는다.

### 2.3 이벤트 릴레이 계층
스냅샷이 못 싣는 "순간"은 명명 메시지로 릴레이한다.

| 메시지 | 방향 | 내용 |
|---|---|---|
| sy_tg / sy_te | H→C | 예고 설치/판정 (시야 필터 통과분만 — 정보 은닉) |
| sy_mv | H→C | 이동 경로 (홉 연출) |
| sy_pu | H→C | **강제 이동(밀침·던지기·낚아채기)** — 없으면 클라에서 순간이동으로 보였다 |
| sy_kl / sy_sk / sy_ps | H→C | 킬·시전·핑 |
| sy_ed | H→C | 라운드 종료 + **호스트 확정치**(거점 소유·생존·종료 사유·매치 스탯) |
| sy_rr | H→C | R 전원 동의 성립 — 재시작 |

**설계 원칙 — 결과 화면은 미러가 아니라 확정치로**: 클라 미러는 스냅샷 지연으로 어긋날 수 있다(실제로 B 거점
소유가 호스트/클라에서 다르게 표시되는 문제 발생). 라운드 종료 페이로드에 호스트 확정 데이터를 실어 해결했다.

### 2.4 시작 시점 레이스와 방어
- `matchSetup에 없는 unitId -1` 예외: 클라가 시작 순간 자기 슬롯을 못 찾음 — 로비 브로드캐스트가 시작 메시지보다 늦는 레이스.
  → **시작 페이로드(ownerClientId)를 정본으로 조회**하고 로비 미러는 폴백으로. 그래도 실패하면 첫 슬롯 폴백 + 에러 로그 (연쇄 붕괴 방지).
- 이탈 처리: 클라 이탈 → 그 유닛에 **봇 드라이버 즉시 승계**, 호스트 이탈 → 클라는 타이틀 복귀.

## 3. 전투 규칙 계층

### 3.1 명중 판정 — 탱고파이브식 엄폐·은신
- 엄폐: 피격자 기준 공격이 날아오는 방향의 인접 벽이 가린다. 정면일수록 빗나감 최대 50%, 옆으로 돌수록 감소.
- 은신: 공격 팀 시야 밖 목표는 50% 빗나감.
- 주사위는 `(예고 id, 피격자 id)` 해시 — **결정론**이라 호스트·클라 재현이 같다.
- 빗나가도 **이동 성분(끌기·밀치기)은 적용** — "엄폐로 몸은 지켜도 위치는 뺏긴다."

### 3.2 탄도 요격 (몸으로 막기)
직선 탄(평타·넉백샷·저격)은 판정 순간 공격선(브레젠험)을 따라 걸으며 **경로 위 첫 적**이 있으면 그 몸에 맞는다.
- 요격은 회피 판정 **면제** — 몸으로 받은 탄은 피할 수 없다 ("차단!" 표시).
- 탱커가 저격선에 서서 딜러를 지키는 플레이가 성립한다.

### 3.3 돌진 계열 통일 — "경로 = 위험"
- 고라니 돌파: 경로 전 유닛 피해+밀침+스턴 (기존).
- 너구리 방패 밀어붙이기·던져버리기: **경로 전체 히트박스**로 확장 + 회피 면제 + **시전자가 목표 칸까지 실제 돌진**
  (`OnCharged` 이벤트 → 뷰 슬라이드 + 바람 줄기 + 클라 릴레이). 밀어낸 자리를 점거하는 자리 싸움이 생겼다.

### 3.4 낚아채기 — 유닛 잠금
- 초기 구현은 "칸"을 기억 → 1초 예고 사이 움직이는 아군 봇을 절대 못 잡았다.
- `TelegraphStrike.targetUnitId` **유닛 잠금**: 판정 시 대상의 현재 칸으로 추적. 아군 낚아채기(구출)는 피해·빗나감 없이 끌기만.
- 착지 칸이 막혀 있으면 주변 8칸 중 원 방향에 가까운 빈 칸으로 대체 착지 (조용한 실패 → "끌려왔다 스냅백" 착시 해소).

### 3.5 행동 제약
- **시전 중 이동 금지**(평타 포함): 예고를 걸면 판정까지 발이 묶인다 — 공격이 "자리를 거는 커밋"이 됐다.
  `MoveSystem.IsCastingFn` 주입으로 코어는 Combat을 모른 채 규칙만 받는다. 잠금 상태 이동 시도엔 "시전 중!" 안내.
- **포위 탈출**: 경로 탐색에서 유닛 칸은 "통과 가능·착지 불가" — 사면이 막혀도 틈새 경로가 계산된다.

### 3.6 거점·라운드
- 점령 저지: 점령 중 피격 시 게이지 30% 삭감 — 화면 게이지는 뚝 끊기지 않고 흘러내린다(사각 파이 스윕).
- 라운드 변형 규칙 5종(봉쇄·고지 장악·경보 해제·단축·탈환 불가)은 **데이터로만 존재**하고 각 시스템이 자기 몫만 조회.
- 종료 사유 7종(전멸/거점 독점/시간-거점/시간-생존/추가시간 킬·탈환)을 시뮬이 기록 — 연출·릴레이의 근거가 된다.

## 4. AI 계층

- **의사결정 우선순위**: 회피 → 선제 설치(습관 카운터) → 공격/스킬 → 거리 유지·근접 대치 → 핑 지휘 → 힐팩 → 거점 → 대기.
- **예측 사격**: 모든 봇이 유닛 이동 경로를 관찰(`ObserveUnitPath`)해 반응 지연을 먹인 조준 칸을 깐다 — 아군 봇의 "읽고 쏘는" 장면이 화면에 등장.
- **핑 지휘**: 휠클릭 핑(▼집결/!집중/?)에 같은 팀 봇이 6초간 복종.
- **규칙 인지**: `ZoneState.Capturable`로 봉쇄·탈환불가 거점을 인지 — 잠긴 거점 앞 멀뚱 현상 제거.
  전 거점이 굳으면 **사냥 모드**(남은 승리 조건은 전멸뿐이므로 최근접 적에게 접근).
- **프리징 워치독**: 3초 무행동 + 유효 거점 밖이면 강제로 한 걸음 — "멀뚱한 AI"를 구조적으로 차단.

## 5. 가독성 — 색 4규칙과 시각 문법

정신없다는 피드백이 반복돼, 탱고파이브를 레퍼런스로 색 채널을 **외울 수 있는 4개**로 압축했다.

| 색 | 의미 |
|---|---|
| 빨강 | 위험 (적 예고 — 흰 바닥에서도 채도 유지 부스트, 나를 노리면 펄스+판정 직전 급점멸) |
| 파랑·노랑 | 내 이동 (파랑 무료 / 노랑 무리) |
| 흰 | 내 조준 (진입 0.3초 플래시 → 저휘도 정착) |
| 회청(어두움) | 아군 참고 정보 (아군 예고) |

- **배틀 매트**: 평시 타일을 눌러(0.6) 하이라이트가 항상 가장 밝게 뜨게.
- **소속 vs 정체 분리**: 스킬 시전은 팀색 링(누구 편) + 스킬 고유색 8종(무슨 스킬)의 이중 문법.
- 발밑 **클래스 링**은 로비 카드 색과 단일 출처(`ClassCard.Meta`) — 카드에서 학습한 색이 전장으로 이어진다.
- 거점: 바닥은 흰 캔버스(딤 제외), 소유는 3겹 네온 테두리(글로우/코어/심지 + 점령 맥동). 봉쇄는 회색 + 밟으면 사유 안내.
- 예고 아이콘은 계기판형(얇은 링 + 유리판 + 흰 아이콘) + **판정까지 차오르는 가는 아크**("긴 시전 = 고장?" 오해 해소).
- Z-파이팅 교훈: 바닥 라인류는 타일 윗면에서 0.1 이상 띄워야 카메라 각도 변화에 안정.

## 6. 연출 계층 — "왜"가 보이는 게임

### 6.1 라운드 종료 킬캠
1. 시뮬이 기록한 종료 사유로 **주인공 선정** — 킬 마감이면 마지막 처치자, 거점 마감이면 마지막 점령자 (호스트·클라 동일 추적).
2. 카메라 스냅 + **클로즈업 돌리 인**(거리 13→7.5, SmoothDamp가 자연스러운 이동을 만든다).
3. **0.25배 슬로우모션 2.1초** — 막타 쓰러짐·점령 장면이 눈에 담긴다.
4. ★ 콜사인 플로팅 + 중앙 사유 대문짝 + **히어로 카드**(기울어진 다크 밴드, 금 라인 개폐, 방사 광원, 슬라이드 인).
5. 결과 패널로 전환. 브리핑 헤더·매치엔드 문구에도 사유 한 줄.

### 6.2 매치 종료 2페이지 + MVP 다부문
- 1페이지: 승/패 밴드(네온 글로우·호흡) + 6인 초상 스트립(기계팀은 전용 회색 일러스트) + 스코어.
- 2페이지: **오버워치식 MVP 스포트라이트** — 대형 일러스트, 금테·코너 브래킷·광택 스윕·떠오르는 불씨.
- MVP는 가중 점수 `킬×100 + 피해×10 + 점령초×9 − 데스×25` — **킬 없는 점령왕도 MVP가 된다.**
  하단에 학살/점령/화력 **부문 수상 배지 3종**. 스탯은 매치오버 시 호스트 확정치로 릴레이.
- R 새 매치는 SPACE와 같은 **전원 동의 게이트** (카운트 표시, 성립 시 전원 로비 복귀).

### 6.3 타격감
- 관련도 위계: 내 유닛 기준 체비셰프 4칸 이내 전투만 크게(1.4배), 먼 전투는 작게(0.8배).
- 마이크로 히트스톱(피해 비례) + 격파 슬로우모(0.3s/0.35배) + 내 공격 적중 시 돌리 펀치·셰이크·썸프.
- War FX 단일 톤 통일(매트 노브 0.42), 폭탄은 대형 WFX_Explosion + 지면 연기 + 충격파 링.
- FxQuad **풀링(128)** — 이펙트 대형화로 늘어난 Instantiate/Destroy 스파이크 제거.

## 7. 파이프라인·도구

- **생성 아트**: GPT Image 2로 카드 일러스트·기계팀 회색 버전(`Card_*_M`, img2img)·UI 프레임 제작.
  검정 캔버스 산출물은 `LoadKeyed`(순검정→투명 + 내용 크롭)로 런타임 키잉 — 소스 수정 없이 재사용.
- **생성 사운드**: Suno + ffmpeg 후처리 파이프라인. "끼에엑" 소음 추적은 **highpass 3.5kHz + volumedetect 스펙트럼 분석**으로
  후보를 정렬한 청취 페이지를 만들어 해결 (범인: S9_Hurt). 낚아채기 SFX는 ffmpeg 합성(노이즈 스윕+저음 턱).
- **절차 생성 우선**: 아이콘(갈고리)·링/글로우/디스크 텍스처·네온 킷 등은 코드로 생성 — 에셋 의존과 임포트 마찰 최소화.
- **검증 루프**: 모든 변경은 `dotnet build Assembly-CSharp.csproj` 즉시 컴파일 검증(신규 .cs는 csproj 수동 등재).
  전투 코어는 EditMode NUnit 회귀 테스트(낚아채기 아군/적, 탄도 요격 등) 동반.
- **동시 작업 충돌**: 팀원과 같은 파일을 상시 병행 수정 — pull --rebase 후 재빌드·수동 병합을 관례화.
  같은 기능(거점 테두리)을 양쪽이 동시 구현한 사례에선 커밋된 쪽을 채택하고 중복을 제거했다.

|---|---|
| ① 코딩 전에 생각하라 | 가정을 명시하고, 해석이 갈리면 묻는다. 더 단순한 방법이 있으면 반박한다. |
| ② 단순함 우선 | 요청 범위만 구현. 1회용 코드에 추상화 금지, 불가능한 시나리오의 예외 처리 금지. "시니어가 과하다고 할 코드인가?" |
| ③ 외과수술식 수정 | 고치라는 것만 고친다. 인접 코드 "개선" 금지, 기존 스타일 준수, 내 변경이 만든 고아 코드만 정리. |
| ④ 목표 주도 실행 | 작업을 검증 가능한 목표로 변환 — "버그 수정" = "재현 테스트를 만들고 통과시키기". |

- Unity 특칙: UI는 프리팹+UIManager 우선, 코드 수정은 승인 전 제시·설명. (본 프로젝트는 팀 합의로 런타임 생성 UI 병용)
- 실전 효과: 과했던 타격감 커밋 즉시 롤백, 중복 구현(거점 테두리)은 커밋된 쪽 채택 — 원칙이 실제 의사결정 기준으로 작동.

### 8.2 caveman 스킬 — 토큰 효율 툴킷

장시간 세션에서 AI 컨텍스트는 유한 자원이다. caveman은 기술 정확도를 유지한 채 언어를 압축해
토큰을 약 75% 절감하는 커스텀 스킬 모음이다.

| 명령 | 역할 |
|---|---|
| /caveman | 압축 대화 모드 — 강도 6단계, 기술 내용 무손실 |
| /caveman-commit | 커밋 메시지 압축 — Conventional Commits, 제목 50자 이내 |
| /caveman-review | PR 리뷰 압축 — 코멘트당 한 줄(위치·문제·수정) |
| /caveman-compress | 메모리 파일(CLAUDE.md·todo) 압축 — 원본 백업 보존 |
| /caveman-stats | 세션 로그 기반 실제 토큰 사용량·절감량 리포트 |
| cavecrew | 서브에이전트 위임 — investigator/builder/reviewer, 압축 응답으로 메인 컨텍스트 수명 연장 |

운영 원칙: 압축은 "말"에만 — 코드·URL·수치는 원형 보존, 사람이 읽는 산출물은 표준 문체로 복원.
